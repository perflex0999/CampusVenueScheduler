# ADR-0001: 选择 Flask 而非 FastAPI

- 状态：已接受
- 日期：2026-11-23

## 决策背景

早期 `docs/02_技术与数据库设计.md` 将后端框架写为「FastAPI（或 Flask）」，二者皆可。代码实现实际为纯 Flask，未使用任何 FastAPI 特性（如依赖注入、Pydantic 模型、异步视图）。

## 决策

保留 **Flask 3.1**，不迁移 FastAPI。

理由：

1. 现有代码在 Flask 下已完整可用，迁移是纯成本、零收益。
2. 业务为单机、SQLite、低并发场景，FastAPI 的异步优势不构成收益。
3. 团队/课程上下文对 Flask 更熟悉，学习成本更低。

## 备选方案

- **迁移 FastAPI**：工作量大，需重写蓝图路由、`session` 认证、错误处理与测试，违背「克制」原则，否决。
- **双框架并存**：文档声明两者，实际只实现其一，会造成误导，否决。

## 后果

- 正面：保持简单，减少依赖与概念负担。
- 负面：放弃 `async` 生态；若未来出现高并发需求需重新评估。
- 文档处置：`docs/02` 中的「FastAPI 或 Flask」措辞应统一为 Flask（见 `docs/` 修正任务）。
