# ADR-0003: 原生 JS 单页应用、无构建工具

- 状态：已接受
- 日期：2026-11-23

## 决策背景

前端需要覆盖多个角色视角（学生、指导教师、场地管理员、系统管理员）的多个页面（工作台、排期日历、预约、审批、台账、审计等）。可在「原生 JS 单文件 SPA」与「框架 + 构建工具（Vue/React）」之间选择。

## 决策

采用 **原生 JavaScript 单文件 SPA**（`app/static/scheduler.js`，hash 路由 + 模板字符串渲染），无框架、无构建步骤、无 npm 依赖。

理由：

1. 前端本质是「调 `/api` JSON + 渲染表单/表格」，无复杂组件状态，原生 JS 足以表达。
2. 去掉 node/npm 构建链路，使项目真正做到「`pip install` 两条命令即可运行」，契合零依赖定位。
3. 需求已稳定，框架带来的可复用性在短期不构成收益。

## 备选方案

- **Vue/React + Vite**：引入 node 工具链、构建产物与依赖审计成本，与「零外部依赖」定位冲突，否决。
- **服务端渲染（Jinja2 多页）**：需为每角色重复模板，交互（日历、弹窗、即时校验）实现更繁琐，否决。

## 后果

- 正面：零构建、部署即运行、体积小。
- 负面：`scheduler.js` 约 810 行，随功能增长需拆分（建议按「页面渲染函数 / API 封装 / 状态」拆成多模块），这是可接受的后续重构，而非当前必需。
