# 校园多功能活动与场地协同调度系统（CampusVenueScheduler）
## 软件需求规格说明书 (SRS)

**文档版本**：v1.0.0  
**更新日期**：2026-05-18  

---

### 一、 引言

#### 1.1 编写目的
本文档明确“校园多功能活动与场地协同调度系统”（CampusVenueScheduler）的业务功能、规则约束、状态流转及数据交互要求，作为该系统研发实现、功能验收与系统测试的技术依据。

#### 1.2 系统范围
本系统面向高校社团、班级及教职部门的日常活动举办需求，提供“活动申报-场地预约-冲突消解-物资借调-多级审批-日历排期”的全流程线上协同管理。系统采用本地自闭环轻量单体架构，提供图形化 Web 交互界面与完整 RESTful 接口。

#### 1.3 术语定义
- **场地 (Venue)**：可供借用举办活动的物理空间（如报告厅、多媒体教室、学生活动室、体育馆等）。
- **预约时段 (Time Slot)**：活动使用场地的具体起始与截止时间。
- **冲突 (Conflict)**：在同一日期内，同一物理场地在时间区间上存在重叠交集的两个或多个预约请求。
- **物资 (Equipment)**：随场地配套借调的活动设备（如无线麦克风、活动展架、便携音响、翻页笔等）。

### 二、 系统总体概述

#### 2.1 用户角色定义
系统内建四类标准用户角色，具备清晰的权限边界：
1. **学生 / 社团成员 (Student / Club)**：
   - 查看场地列表、场地容量、配套设备及当前排期占用日历；
   - 提交活动方案与场地/物资借用申请；
   - 查看个人申请历史、当前审批状态与审批驳回原因；
   - 在活动开始前取消已申报的预约。
2. **社团指导教师 / 院级初审人 (Advisor)**：
   - 对本科室/本学院学生发起的活动内容合规性进行第一级业务初审；
   - 填写初审意见（同意流转至场地审批 / 驳回修改）。
3. **场地与资产管理员 (Venue Manager)**：
   - 维护场地基础信息（名称、编号、容纳人数、所属楼宇、开放时段、启用/停用）；
   - 维护配套活动物资信息及库存数量；
   - 对通过初审的活动进行最终场地排期与物资调配审批；
   - 手动设置场地因维护、临时考试等不可用时段（场地锁定）。
4. **系统管理员 (System Admin)**：
   - 用户账号维护（重置密码、角色变更、停用启用）；
   - 基础字典与系统运行审计日志查看；
   - 系统演示数据一键初始化与重置。

#### 2.2 核心业务概念模型
- 一个【场地】可容纳多个在不同时间段举行的【活动预约】；
- 一次【活动预约】归属于一个【申报用户】，绑定一个【主场地】，可附带多项【物资借调申请】；
- 每次预约具备全局唯一的状态流转履历。

### 三、 详细功能需求

#### 3.1 账号与身份认证模块
- **FR-AUTH-01 登录与鉴权**：
  - 用户通过工号/学号与密码登录系统，成功后颁发基于 Session/Token 的身份标识；
  - 非法账号、密码错误应即时拦截并给出明确提示，连续输错 5 次提示锁定 5 分钟；
  - 界面右上方常驻显示当前登录用户名、所属角色标签及安全注销按钮。
- **FR-AUTH-02 个人中心与密码修改**：
  - 用户可修改个人联系电话、邮箱及登录密码；
  - 新密码长度不小于 6 位，需二次确认。

#### 3.2 场地资源管理模块
- **FR-VEN-01 场地列表与多维检索**：
  - 支持按楼宇位置（如信科楼、综教楼、学活中心）、场地类型、容纳人数区间及当前可用状态组合筛选；
  - 支持分页浏览，单页展示场地名称、编号、座位数、设备配置简述及状态标签。
- **FR-VEN-02 场地详情与开放配置**：
  - 展示场地全景描述、最高承载人数、配备物资清单（如投影幕布、话筒接口数等）；
  - 支持管理员配置常规开放时段（如每日 08:00 - 22:00），非开放时段禁止发起预约。
- **FR-VEN-03 场地状态维护**：
  - 管理员可将场地标记为“正常开放”或“维护检修中”；处于维护状态的场地在日历上置灰，禁止提交新预约。

#### 3.3 活动申报与预约调度模块
- **FR-ACT-01 发起活动预约申请**：
  - 申报人填写活动基本信息：活动主题、活动类型（学术讲座、社团排练、文娱活动、班级例会）、预期参与人数、活动简要介绍；
  - 选择预约日期与具体使用时段（起始时间、结束时间，步长以 30 分钟为基本单位）；
  - 勾选附带借用的物资及数量（如：无线麦克风 2 支、音响 1 套）。
- **FR-ACT-02 前置合规性校验**：
  - **容量超限拦截**：申报预期人数不得超过所选场地核定最大容量，否则表单禁止提交并红字警告；
  - **时间合规校验**：起始时间必须早于结束时间，单次活动持续时长不得少于 30 分钟且不得超过 8 小时；预约时间必须晚于当前系统时间（禁止跨天向前追溯历史时间预约）。
- **FR-ACT-03 取消预约申请**：
  - 对于处于“待审核”或“已批准”状态的活动，申报人在活动起始时间前至少 2 小时可主动取消预约；
  - 取消后场地排期立即释放，借调的物资库存自动返还。

#### 3.4 场地排期看板与智能冲突判定
- **FR-SCH-01 场地时空排期日历**：
  - 提供日历视图与甘特排期时间轴，直观展示指定场地在选定日期内的所有已被占用、待审核时段；
  - 不同状态以明确视觉标识区分（蓝色：已批准占用；黄色：审核中预占用；灰色：不可用/已闭馆）。
- **FR-SCH-02 核心冲突检测规则 (Conflict Engine)**：
  - 设已有有效预约时段为 $[S_A, E_A)$，新申请预约时段为 $[S_B, E_B)$；
  - **时空冲突判定准则**：在同一场地、同一日期内，当且仅当满足下述条件时触发冲突拦截：
    $$S_A < E_B \quad \land \quad S_B < E_A$$
  - **接缝允许准则**：相邻预约时间首尾相接不判定为冲突（例如：$14:00 \sim 15:00$ 与 $15:00 \sim 16:00$ 为合规衔接）；
  - **冲突处理行为**：若提交申请时与已有“已批准”预约存在时间交集，系统即时阻止提交，并在界面标红展示冲突冲突活动的名称与时段。

#### 3.5 物资协同管理模块
- **FR-EQP-01 物资台账与可用库存**：
  - 管理员维护系统物资基础库：物资名称、资产编号、总库存量、单次活动最大借用限额；
  - 动态计算并展示指定日期的物资“剩余可用库存 = 总库存 - 同一时段内已被批准占用的总数”。
- **FR-EQP-02 物资借调约束校验**：
  - 申报人申请物资数量不得超过该物资单次允许上限；
  - 若所需物资在指定时间段内可用库存不足，系统进行阻断或友好警示。

#### 3.6 多级审批与工作流闭环
- **FR-APPR-01 待办审批流水列表**：
  - 审批人工作台展示待其处理的申请列表，支持按申请时间、活动日期排序；
  - 点击可查看完整申报方案、安全承诺说明、场地冲突核验状态。
- **FR-APPR-02 审批动作与日志追溯**：
  - 审批人可执行“批准”或“驳回”；
  - 驳回时必须强制填写驳回原因（不少于 5 个字），以便学生查看整改；
  - 审批通过后，系统正式锁定该场地时段排期与物资库存。

### 四、 核心状态机模型

活动预约单在系统中的生命周期流转状态定义如下：

| 状态标识 | 中文名称 | 说明 | 允许的后续操作 |
| :--- | :--- | :--- | :--- |
| `DRAFT` | 草稿 | 用户已保存但未提交初审 | 编辑、提交、删除 |
| `PENDING_ADVISOR` | 待指导教师初审 | 已提交，等待指导教师审查内容合规性 | 初审通过、初审驳回、用户主动取消 |
| `PENDING_VENUE` | 待场地管理员终审 | 初审通过，等待场地排期与设备终审 | 终审批准、终审驳回、用户主动取消 |
| `APPROVED` | 预约已批准 | 终审通过，场地与物资已被正式锁定占用 | 用户在规定时限前取消、管理员变更 |
| `REJECTED` | 已驳回 | 初审或终审未通过，附带驳回原因说明 | 查看驳回意见、修改后重新提交 |
| `CANCELLED` | 已取消 | 用户或管理员在生效前主动撤销预约 | 归档查看，场地物资已释放 |
| `FINISHED` | 已结束 | 活动截止时间已过，自动流转为完成归档 | 查看历史记录 |

### 五、 非功能性与运行环境要求

1. **完全自闭环运行**：
   - 系统仅依赖 Python 3.12+ 官方运行环境及标准第三方依赖包；
   - 数据库使用内置文件型 SQLite，部署无须单独安装配置外部独立数据库服务，一键初始化即跑通；
2. **易用性与界面体验**：
   - 采用标准桌面 Web 界面，布局主次分明，操作流转具备面包屑导航；
   - 所有表单提交均具备即时输入校验，错误提示位于字段下方或居中浮层，信息平实易懂；
   - 表格均支持多条件模糊筛选与自适应宽度。
3. **安全与稳定性**：
   - 核心业务写操作（审批、预约、取消）具备数据库事务保障；
   - 数据输入具备防 SQL 注入与特殊字符转义。
