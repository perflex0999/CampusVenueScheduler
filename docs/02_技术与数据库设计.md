### 一、 系统技术选型与总体架构

#### 1.1 技术栈选型
为保证系统的高可移植性、完全自闭环运行与零外部服务依赖，选型如下：
- **后端框架**：Python 3.12+ + Flask（标准化轻量 Web 路由）
- **数据持久化**：内置 SQLite 3（数据库文件位于 `var/campus_scheduler.sqlite3`）
- **前端技术**：现代化标准 Web 页面（HTML5 + 原生 CSS + 原生 JavaScript 单页应用，支持响应式与自适应布局，无须 node 构建打包，开箱即运行）
- **数据交互协议**：RESTful JSON API（由原生 JS 单页应用调用）

### 三、 核心服务与调度算法设计

#### 3.1 时空冲突检测核心算法实现设计
在提交新预约申请或进行最终场地审批时，系统服务层调用 `overlapping_reservation` 进行防冲突判定（实际实现见 `app/services/venue_service.py`，返回冲突记录或 `None`）：

```python
def overlapping_reservation(db, venue_id: int, target_date: str, start_time: str, end_time: str, exclude_res_id: int = None) -> bool:
    """
    检查指定场地在特定日期的 [start_time, end_time) 是否与已有有效预约冲突。
    有效预约定义为：状态处于 'APPROVED' 或 'PENDING_VENUE'（预占用）。
    冲突条件：已有时段 (S_exist < end_time) 且 (S_new < E_exist)。
    返回 True 表示存在冲突（不可借），False 表示无冲突（可借）。
    """
    query = """
        SELECT id, title, start_time, end_time, status 
        FROM reservations 
        WHERE venue_id = :venue_id 
          AND reserve_date = :target_date
          AND status IN ('APPROVED', 'PENDING_VENUE')
          AND start_time < :end_time 
          AND :start_time < end_time
    """
    params = {
        "venue_id": venue_id,
        "target_date": target_date,
        "start_time": start_time,
        "end_time": end_time
    }
    if exclude_res_id:
        query += " AND id != :exclude_res_id"
        params["exclude_res_id"] = exclude_res_id

    conflicts = db.execute(query, params).fetchall()
    return len(conflicts) > 0
```

#### 3.2 物资动态可用库存计算服务
```python
def available_quantities(db, equipment_id: int, target_date: str, start_time: str, end_time: str) -> int:
    """
    动态计算指定物资在指定时间区间的剩余可用库存。
    公式：总库存 - 同一时段内已被 APPROVED 的占用数量总和。
    """
    total_qty = db.execute("SELECT total_qty FROM equipments WHERE id = :id", {"id": equipment_id}).scalar()
    
    occupied_qty = db.execute("""
        SELECT COALESCE(SUM(re.quantity), 0)
        FROM reservation_equipments re
        JOIN reservations r ON re.reservation_id = r.id
        WHERE re.equipment_id = :equipment_id
          AND r.reserve_date = :target_date
          AND r.status = 'APPROVED'
          AND r.start_time < :end_time 
          AND :start_time < r.end_time
    """, {"equipment_id": equipment_id, "target_date": target_date, "start_time": start_time, "end_time": end_time}).scalar()
    
    return max(0, total_qty - occupied_qty)
```

### 四、 核心 REST API 规范接口设计

| 路由路径 | 请求方法 | 权限要求 | 接口用途与功能描述 |
| :--- | :--- | :--- | :--- |
| `/api/auth/login` | POST | 匿名 | 提交学号/密码，验证通过颁发鉴权 Session / Token |
| `/api/auth/logout` | POST | 已登录 | 清除会话，安全注销 |
| `/api/venues` | GET | 已登录 | 条件检索场地列表（支持楼宇、类型、容量筛选与分页） |

| `/api/admin/reset-demo` | POST | 系统管理员 | 重新执行初始化脚本，清空临时数据并恢复初始预设 |
